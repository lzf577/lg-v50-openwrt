### 一、 问题诊断与研判（事实确诊）

副指挥官经实地探测排查：
1. **服务未启动**：系统冷重启后，`uhttpd`（OpenWrt 的 Web 服务器）尚未加入自启动脚本中，进程列表无 `uhttpd`；
2. **环境完整可用**：OpenWrt 根目录的 `/www`、`/etc/config/uhttpd`、`/etc/init.d/uhttpd` 以及 LuCI 静态与 CGI 资源均完备有效，手动调用 `/etc/init.d/uhttpd start` 可正常拉起并在 80/443 端口监听并正常响应 LuCI 页面；
3. **两类访问场景**：
   - **Wi-Fi 客户端访问**：连接 `OpenWrt-V50-5G` 的手机/电脑，直接通过浏览器访问网关 `http://192.168.10.1` 即可进入 LuCI；
   - **PC USB (ADB) 访问**：开发机通过 ADB 端口映射（如 `adb forward tcp:8080 tcp:80`），通过 `http://127.0.0.1:8080` 进入 LuCI。

### 二、 执行任务

1. 将 `uhttpd` Web 服务器正式纳入系统启动栈，确保立即生效；
2. 更新 Magisk 开机自启脚本 `/data/adb/service.d/99-openwrt-takeover.sh`，在拉起 `hostapd` 后自动启动 `/etc/init.d/uhttpd start`；
3. 为电脑端配置 ADB 端口映射规则，并进行双向浏览器访问验证。

### 三、 执行步骤与规范

#### 步骤 7.1：立即拉起当前 OpenWrt 内部的 uhttpd 服务
通过 SSH 2222 端口或 ADB 进入 OpenWrt 启动 Web 服务：
```bash
ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null root@127.0.0.1 '
/etc/init.d/uhttpd start
ps | grep uhttpd
netstat -nlpt | grep :80
'
```
*必须确认 80 端口进入 LISTEN 状态。*

#### 步骤 7.2：将 uhttpd 固化进 Magisk 自启动脚本
更新宿主 Android 端的 `/data/adb/service.d/99-openwrt-takeover.sh`，在 `hostapd` 启动后追加拉起 `uhttpd`：
```bash
adb shell su -c '
cat << "EOF" > /data/adb/service.d/99-openwrt-takeover.sh
#!/system/bin/sh
# OpenWrt Takeover Autostart Service for LG V50

LOG_FILE=/data/local/tmp/openwrt_autostart.log
exec > "$LOG_FILE" 2>&1

echo "=== [$(date)] OpenWrt Autostart Initiated ==="

# 1. 等待 Android 系统完全启动
while [ "$(getprop sys.boot_completed)" != "1" ]; do
    sleep 3
done
echo "=== sys.boot_completed detected, waiting for cnss-daemon ==="

# 2. 等待高通 WLAN 守护进程就绪
while [ "$(getprop init.svc.cnss-daemon)" != "running" ]; do
    sleep 2
done
# 缓冲 5 秒确保平台稳固
sleep 5
echo "=== cnss-daemon ready, releasing Android Wi-Fi stack ==="

# 3. 安全停止 Android Wi-Fi 栈
setprop ctl.stop wpa_supplicant
setprop ctl.stop wificond
setprop ctl.stop vendor.wifi-hal-1-1
setprop ctl.stop vendor.wifi_hal_legacy
setprop ctl.stop vendor.wifidisplayhalservice

# 4. 挂载 OpenWrt 环境
M=/data/local/tmp/lede
mkdir -p $M
mount -t ext4 -o rw /dev/block/sda25 $M
mount -o bind /dev $M/dev
mount -t proc proc $M/proc
mount -t sysfs sysfs $M/sys
mkdir -p $M/vendor && mount -o bind /vendor $M/vendor

# 5. 在 Mount 命名空间启动 OpenWrt 容器与服务
nohup unshare -m chroot $M /bin/busybox sh -c "
  export PATH=/usr/sbin:/usr/bin:/sbin:/bin
  mkdir -p /tmp /run /var/run/ubus /var/lock /var/log /etc/dropbear
  mount -t tmpfs tmpfs /tmp 2>/dev/null
  mount -t tmpfs tmpfs /run 2>/dev/null

  # 检查或补齐 Dropbear key
  if [ ! -s /etc/dropbear/dropbear_ed25519_host_key ]; then
    dropbearkey -t ed25519 -f /etc/dropbear/dropbear_ed25519_host_key
  fi

  # 启动核心进程
  /sbin/ubusd &
  sleep 1
  /sbin/procd &
  sleep 1

  # 启动 SSH
  /usr/sbin/dropbear -R -B -p 127.0.0.1:2222

  # 配置并拉起 Wi-Fi 与 DHCP
  ip link set wlan0 down
  ip link set wlan0 up
  ip addr flush dev wlan0
  ip addr add 192.168.10.1/24 dev wlan0

  killall dnsmasq 2>/dev/null
  dnsmasq -C /etc/dnsmasq-v50.conf

  killall hostapd 2>/dev/null
  hostapd -B -P /tmp/hostapd.pid /etc/hostapd/hostapd-5g.conf

  # 启动 Web 界面服务 (uhttpd)
  /etc/init.d/uhttpd restart
" > /data/local/tmp/lede_takeover.log 2>&1 &

echo "=== [$(date)] OpenWrt Autostart Trigger Complete ==="
EOF

chmod 755 /data/adb/service.d/99-openwrt-takeover.sh
chown root:root /data/adb/service.d/99-openwrt-takeover.sh
'
```

#### 步骤 7.3：配置 PC 端访问端口映射与测试
在 PC 宿主机执行：
```bash
adb forward tcp:8080 tcp:80
```
- 测试 1：在 PC 终端执行 `curl -i http://127.0.0.1:8080/`，核验返回 `HTTP/1.1 200 OK` 或重定向；
- 测试 2：连接 Wi-Fi 热点 `OpenWrt-V50-5G` 的手机或电脑，在浏览器打开 `http://192.168.10.1/`，核验是否正常呈现 LuCI 登录页面。
