### 一、 架构裁决与调整背景

在执行指令 03 的步骤 2.4 时，工兵准确确诊：
- **物理事实**：LG V50 原厂官方内核未开启 `CONFIG_PID_NS`（`# CONFIG_PID_NS is not set`），故不支持 `unshare -p -f` 隔离 PID。但 `CONFIG_NAMESPACES` 与 `CONFIG_NET_NS` 均完备，且 Mount 命名空间 `unshare -m` 完全正常。
- **降级预案执行**：依据《定稿流程》第 143 行规范（“降级：若 OpenWrt 标准的 preinit 在 chroot 内失败，不要改镜像。回报日志，由副指挥研判是否改为直接运行 procd”），副指挥官调整启动架构为：
  1. 隔离挂载空间（`unshare -m`）；
  2. 补齐 Dropbear ed25519 host key（清除损坏的 0 字节 key 并重新生成）；
  3. 依次拉起核心基础服务 `ubusd` 与 `procd`，启动 SSH 服务；
  4. 电脑端端口转发并验证 `ubus list` 与 `ps`。

---

### 二、 执行步骤与命令规范

#### 1. 清理并初始化环境
在手机端执行清理与目录挂载：
```bash
adb shell su -c '
M=/data/local/tmp/lede
killall -9 dropbear ubusd procd 2>/dev/null
umount $M/sys 2>/dev/null
umount $M/proc 2>/dev/null
umount $M/dev 2>/dev/null
umount $M/vendor 2>/dev/null
umount $M 2>/dev/null

mkdir -p $M
mount -t ext4 -o rw /dev/block/sda25 $M
mount -o bind /dev $M/dev
mount -t proc proc $M/proc
mount -t sysfs sysfs $M/sys
mkdir -p $M/vendor && mount -o bind /vendor $M/vendor
'
```

#### 2. 生成 host key 与拉起 OpenWrt 核心
```bash
adb shell su -c '
M=/data/local/tmp/lede
nohup unshare -m chroot $M /bin/busybox sh -c "
  export PATH=/usr/sbin:/usr/bin:/sbin:/bin
  mkdir -p /tmp /run /var/run/ubus /var/lock /var/log /etc/dropbear
  mount -t tmpfs tmpfs /tmp 2>/dev/null
  mount -t tmpfs tmpfs /run 2>/dev/null

  # 确保 host key 正常
  rm -f /etc/dropbear/dropbear_*_host_key
  dropbearkey -t ed25519 -f /etc/dropbear/dropbear_ed25519_host_key

  # 启动 ubusd
  /sbin/ubusd &
  sleep 1

  # 启动 procd (后台模式)
  /sbin/procd &
  sleep 1

  # 启动 Dropbear SSH
  /usr/sbin/dropbear -R -B -p 127.0.0.1:2222
" > /data/local/tmp/lede_takeover.log 2>&1 &
'
```

#### 3. PC 端端口转发与验收测试
在电脑端执行：
```bash
sleep 3
adb forward tcp:2222 tcp:2222
ssh -p 2222 -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null root@127.0.0.1 "ubus list; ps | grep -E 'ubusd|procd|dropbear'"
```
